# Sign in with ChatGPT

対象は利用者自身の PC で動かす Web 版。公式の OSS 向け OAuth フローを使い、公開 Responses API に接続する。Codex や ChatGPT の既存認証ファイルは読み込まない。

## 接続

1. Settings → Models → 「モデルプロバイダーを追加」を押し、プロバイダーで Sign in with ChatGPT を選ぶ。
2. 「Continue with ChatGPT」を押す。Tailscale などの非ローカル画面では、認証後のURL貼り付け手順がモーダルに出る。「確認して進む」を押すと、戻り先URLの入力欄を表示してフォーカスを当ててから認証タブが開く。元のタブに戻ったら、そのまま貼り付けられる。ローカル画面では直接開く。
3. ChatGPT 側でアカウントと利用権限を確認する。Tailscale などの非ローカル画面では、元の dsh 画面に戻り先URLの入力欄が現れる。ローカル画面では自動で戻るため、この入力欄は出ない。ポップアップがブロックされた場合だけ、元の画面の認証リンクを押して開く。
4. 同じPCのブラウザーなら完了表示後に dsh へ戻る。別のPCから開いていて 127.0.0.1 に接続できない場合は、アドレスバーのURL、または「?」以降のクエリを dsh の「ブラウザーの戻り先URL」へ貼り、「認証を完了」を押す。http:// が欠けていてもよい。入力内容はそのまま表示する。
5. モデル選択で Sign in with ChatGPT と利用可能モデルを選ぶ。

追加・編集画面は、他のプロバイダーと同じ編集パネルと右寄せの操作欄を使う。認証中は別タブを開いた状態、開き直すリンク、URL入力欄と「キャンセル」「認証を完了」を表示する。使用量リンクは接続後の詳細に表示する。

ChatGPTの接続中は、モデル一覧の取得が一時的に失敗していても、初回のDeepSeekログイン・APIキー案内を自動で出さない。

接続後は、他のプロバイダーと同じ一覧に折りたたみ行として表示する。「編集」を押すと接続中アカウントの詳細を開く。接続中のアカウントの再認証には「再接続」を使う。切り替え欄は設けず、別のアカウントを使う場合はログアウトしてから追加し直す。同じメールアドレスでも登録は統合しない。「使用量を管理」は ChatGPT の使用量設定を開く。

モデル一覧はそのアカウントから取得し、同梱 pi-ai カタログに能力情報があるモデルだけを表示する。新しいモデルが表示されないときはアプリの更新を確認する。

## 保存と認証経路

本体の既存 credential store が、専用の llm-pi-ai/chatgpt レコードにホスト ID、登録ごとの client ID、検証済み本人情報、トークン、許可された scope を保存する。更新トークンの交換は credential store のプロセス間ロック内で行う。

Sign in with ChatGPT は API キーへ自動で切り替えない。OPENAI_API_KEY の有無はこのプロバイダーの認証経路に影響しない。ChatGPT 側のクレジット利用設定は利用者自身が使用量設定で確認する。

ログアウトでは更新可能なセッションの失効を試み、ローカルトークンを削除する。ホスト ID と登録情報は再接続用に内部で保持するが、ログアウト済みのアカウント情報は画面の一覧・選択肢に出さない。ログアウト時には現在の選択を解除し、ほかの登録へ自動で切り替えない。最後のアカウントをログアウトすると、ChatGPT の行自体が一覧から消える。再接続する場合は、プロバイダー追加から選び直す。ネットワーク障害などで失効を確認できなかった場合は、画面の案内に従って ChatGPT 側から接続を解除する。

## 初回の実通信確認

実アカウントでのブラウザー認証は利用者が行う。まず短いテキスト応答を確認し、その後で使い捨て作業ディレクトリ内のファイル読取・編集・テストを確認する。最後に dsh を再起動して履歴から続行できるか確認する。資格情報や OAuth URL を検証記録へ貼らない。

Tailscale 経由のブラウザーでは、OpenAI が要求する loopback の戻り先を直接 Tailscale のドメインへ変更できないため、上記の貼り付け方式を使う。戻り先URLに含まれる認証コードをチャットやログへ貼らない。古い試行のURLや、再起動前のURLは使えない。

Desktop のパッケージ配布、他の OS、SSH 先での認証移送は今回の検証範囲に含めない。
