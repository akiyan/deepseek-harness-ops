# ChatGPT プランと OpenAI API キーの接続

2026-11-21 の時雨堂追随から、旧 akiyan 独自の `chatgpt` ではなく、時雨堂・pi-ai の標準認証を使用する。

## 接続先の使い分け

| 用途 | プロバイダー ID | 操作 |
|---|---|---|
| ChatGPT プランで使う | `openai-codex` | `OpenAI (ChatGPT plan)` の OAuth ログイン |
| OpenAI API キーで使う | `openai` | API キー方式を選んで保存、または `apiKeyEnv: OPENAI_API_KEY` を明示 |

追加の API キー専用プロバイダーは作らない。上流は `openai` 自体にも任意の ChatGPT ログインを提供するが、この fork の利用手順ではプラン利用を `openai-codex`、API キー利用を `openai` に分ける。`openai` に API キーの参照を明示すると、保存済み OAuth よりその参照が優先される。プラン利用を意図したセッションでは、モデルとともに `openai-codex` を選択する。

## ChatGPT プランで接続する

1. Settings → Models で `openai-codex`（表示名 `OpenAI (ChatGPT plan)`）を選び、ログインを開始する。
2. 表示されたリンクから OpenAI の認証画面を開き、利用者自身でアカウントと権限を確認する。
3. 同じ端末ならブラウザーの戻りを待つ。別端末・Tailscale 経由の場合は、標準ログイン画面が求める戻り先 URL の貼り付けを行う。loopback の URL に到達できない場合でも、その URL を入力欄に戻す。古い独自モーダルの表示・操作順には依存しない。
4. 接続後、セッションのモデル選択でも `openai-codex` と利用可能モデルを選ぶ。

契約・組織ポリシーによる利用可否は OpenAI が判断する。認証 URL に含まれるコード・トークン・クエリをチャットや公開ログへ貼らない。

## API キーで接続する

Settings → Models の `openai` で API キー方式を選ぶ。資格情報ストアへの保存、または `OPENAI_API_KEY` の参照を使い、キーそのものを設定ファイルへ書かない。独自エンドポイントを使う既存の `openai` プロファイルは維持できる。ChatGPT 側の認証の削除で `openai` の API キーが削除されることはない。

## 旧 akiyan 実装からの移行

旧 `chatgpt` は独自の OAuth クライアント登録・資格情報形式を使用していた。新しい `openai-codex` と形式・発行先が同一とはみなさず、資格情報のコピーや自動変換は行わない。

- 更新前に、サービスを停止した状態で DSH_HOME と資格情報を非公開領域へバックアップする。[復旧手順](recovery.md)を参照する。
- 更新後に `openai-codex` で再ログインし、旧 `chatgpt` を選択していた既存セッション・既定モデル・サブエージェント設定のプロバイダーを選び直す。
- 過去の会話ログや旧資格情報レコード `llm-pi-ai/chatgpt` は書き換え・削除しない。旧レコードが残っていても標準経路では利用されない。
- 接続先を変更しても旧会話の継続時に問題が出る場合は、新規セッションで確認する。旧認証の失効が必要なら、OpenAI 側の接続管理から利用者が解除する。
- `llm-pi-ai/chatgpt` を `llm-pi-ai/openai-codex` に単純に改名しない。

## 検証範囲

自動テストは OAuth イベント、戻り先 URL 入力、資格情報の分離、API キー経路、および設定 UI を扱う。外部認証通信を置き換えた結果と、実アカウントの認証・推論は区別する。今回、実アカウントの再認証や課金を伴う推論は実施しない。利用者による再認証後、短いテキスト応答と再起動後の継続を確認する。

旧独自実装の画面と `chatgpt/account` を対象とする運用リポジトリ内の UI スクリプトは過去版専用であり、現行版には実行しない。現行の重点検証コマンドは[今回の記録](../releases/2026-11-21.md)に記す。
