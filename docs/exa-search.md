# Exa ウェブ検索

プラグイン一覧から「Exa検索の設定」を開く。「ウェブ検索にExaを使う」をオンにして保存すると、検索だけが Exa に切り替わる。ページ取得の設定は変わらない。

APIキーは任意。キーなしでは Exa の匿名 MCP を使い、共有の利用制限を受ける。キーを入力して保存すると、資格情報ストアの `EXA_API_KEY` に保存し、以後は REST API の利用枠で検索する。起動環境の `EXA_API_KEY` も使える。キーを保存しても、検証のための検索は自動実行しない。

結果数の既定は5件で、設定できる範囲は1〜100件。ツールの呼び出し側が件数を指定した場合はそちらを使う。無料枠を確認するためだけに検索を繰り返さず、使用量は Exa の管理画面で確認する。

入力欄は保存済みのキーを読み戻さず、保存成功後に空になる。「APIキーを削除」で保存済みキーを削除すると、起動環境からもキーが供給されていない場合は匿名 MCP に戻る。起動環境などの読み取り専用レイヤーのキーは、この画面から削除できない。

匿名側の利用制限や REST の認証エラーは検索失敗として表示する。認証に失敗したキーを匿名検索へ自動で切り替えたり、同じ要求を自動で再試行したりしない。

プロファイルの `web-search-exa` 行では `baseURL`、`mcpURL`、`maxResults`、`timeoutMs`、`maxResponseBytes` を設定できる。エンドポイント変更時も、資格情報や認証付き URL を公開文書・Issue に貼らない。

実接続の確認は検索1回・結果1件で実施した。通常の回帰テストと UI 検証は仮データを使い、API の利用枠を消費しない。
